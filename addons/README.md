# Дополнения Home Assistant

Контейнерные дополнения работают в независимом Compose-проекте `ha-addons`. Основной стек находится в `../homeassistant`, инструменты администрирования — в `../tools`. Все контейнерные дополнения по умолчанию отключены. Пользовательские интеграции HA, включая пример Yandex Smart Home, описаны отдельно в [integrations/readme.md](../integrations/readme.md).

```text
addons/
  docker-compose.yml
  .env
  zigbee2mqtt/
    README.md
    data/
      .stub               # каталог существует после клонирования
  hass-configurator/
    README.md
    data/
      .stub
  matter-server/
    README.md
    data/
      .stub
```

Команды ниже выполняются на Raspberry Pi внутри клона `home_assistant_config/`, созданного по [основной инструкции](../readme.md#клонирование-репозитория). Пример корня проекта — `/home/hauser/home_assistant_config`; основной стек находится в `homeassistant/`, дополнения — в `addons/`, скрипты — в корневом `system/`. Для скриптов нужны Bash, Python 3.9+ и Docker Compose v2.27+; Python использует только стандартную библиотеку.

## Подготовка в клоне репозитория

Каталоги `data/` контейнерных дополнений должны существовать **до первого запуска**. В Git для каждого из них сохранён пустой файл `.stub`, поэтому каталоги появляются при клонировании. Для существующей установки или нового дополнения их можно подготовить явно; `mkdir -p` сохраняет имеющиеся данные:

```bash
cd /home/hauser/home_assistant_config
mkdir -p addons/zigbee2mqtt/data addons/hass-configurator/data addons/matter-server/data
```

Рабочее содержимое `data/` исключено из Git; публикуется только пустой `.stub`. На существующей установке используйте свои данные и не проходите первоначальную настройку Zigbee- или Matter-сети повторно.

Создайте локальный `.env`, сохраняя уже существующий, и заполните параметры выбранных дополнений:

```bash
cd /home/hauser/home_assistant_config/addons
[ -e .env ] || (umask 077; cp .env.example .env)
chmod 600 .env
nano .env
bash ../system/addons.sh validate
```

## Выбор дополнений

В `.env` задаётся одна строка `COMPOSE_PROFILES`:

| Строка | Включённые контейнеры |
| --- | --- |
| `COMPOSE_PROFILES=` | Ни одного |
| `COMPOSE_PROFILES=zigbee2mqtt` | Zigbee2MQTT |
| `COMPOSE_PROFILES=hass-configurator` | File Editor |
| `COMPOSE_PROFILES=matter-server` | Matter Server |
| `COMPOSE_PROFILES=zigbee2mqtt,hass-configurator` | Zigbee2MQTT и File Editor |
| `COMPOSE_PROFILES=zigbee2mqtt,matter-server` | Zigbee2MQTT и Matter Server |
| `COMPOSE_PROFILES=hass-configurator,matter-server` | File Editor и Matter Server |
| `COMPOSE_PROFILES=zigbee2mqtt,hass-configurator,matter-server` | Все три |

Профили — штатный механизм [Docker Compose](https://docs.docker.com/compose/how-tos/profiles/). Переменные окружения терминала имеют приоритет над `.env`; удалите старый экспорт `COMPOSE_PROFILES` через `unset COMPOSE_PROFILES`, если хотите использовать файл. Скрипт отклоняет неизвестные профили и `*`, чтобы опечатка не оставляла неожиданное состояние.

| Переменная | Назначение |
| --- | --- |
| `HA_DIR` | Основной стек для общего `config/` File Editor; по умолчанию `../homeassistant`, относительно каталога Compose дополнений |
| `HA_BACKEND_NETWORK` | Имя общей сети; одинаковое в основном стеке и дополнениях, по умолчанию `ha-backend` |
| `ADDONS_BIND_IP` | Адрес веб-интерфейсов; `127.0.0.1` по умолчанию, для LAN укажите LAN IPv4 сервера |
| `ZIGBEE2MQTT_PORT`, `HASS_CONFIGURATOR_PORT` | Порты хоста, по умолчанию `8080` и `3218` |
| `ZIGBEE2MQTT_IMAGE`, `HASS_CONFIGURATOR_IMAGE`, `MATTER_SERVER_IMAGE` | Образы с выбранными версиями или digest |
| `ZIGBEE_ADAPTER_PATH` | Путь к координатору на хосте, желательно `/dev/serial/by-id/...`; нужен только Zigbee2MQTT |
| `HC_USERNAME`, `HC_PASSWORD` | Логин и непустой пароль; нужны только включённому File Editor |
| `MATTER_PRIMARY_INTERFACE`, `MATTER_BLUETOOTH_ADAPTER` | Интерфейс с IPv6 и индекс BlueZ для Matter; по умолчанию `wlan0`, `0` |

Пароль заключайте в одинарные кавычки, чтобы `$` оставался буквальным символом. Рабочие `.env` и данные не публикуются. Скрипт не исполняет `.env` как shell-код и не выводит пароль. Для выключенного File Editor пароль не требуется; для выключенного Zigbee2MQTT координатор не требуется. Скрипт не знает названий дополнений, не проверяет пароли, координаторы или настройки приложений: пользователь заполняет их по инструкции дополнения, а ошибки обнаруживают Docker и само приложение при запуске.

## Применение и отключение

Сначала подготовьте и запустите основной стек по [основной инструкции](../readme.md#первый-запуск-сервисов), затем выберите профили и выполните:

```bash
bash /home/hauser/home_assistant_config/system/addons.sh validate /home/hauser/home_assistant_config/addons
bash /home/hauser/home_assistant_config/system/addons.sh apply /home/hauser/home_assistant_config/addons
bash /home/hauser/home_assistant_config/system/addons.sh check /home/hauser/home_assistant_config/addons
```

Команды скрипта:

| Команда | Действие |
| --- | --- |
| `validate` | Проверить разбор Compose и выбор профилей без Docker daemon и изменений; параметры приложений не проверяются |
| `apply` | Проверить принадлежность контейнеров проекту, скачать образы выбранных сервисов, удалить отключённые контейнеры и запустить выбранные |
| `start` | Применить тот же выбор без скачивания образов; используется единым скриптом и автозапуском |
| `stop` | Остановить все контейнеры своего проекта, включая оставшиеся отключённые сервисы, сохранив контейнеры и данные |
| `check` | Проверить состав контейнеров, состояние, политику перезапуска и Docker healthcheck, если он задан, без изменений |

Чтобы отключить дополнение, удалите его имя из `COMPOSE_PROFILES` и снова выполните `apply`. Для отключения всех оставьте пустое значение. Скрипт останавливает и удаляет контейнеры своего Compose-проекта по меткам Docker, включая сервисы, удалённые из Compose; одноразовые `docker compose run` пропускаются. Каталоги данных, тома и образы сохраняются. При пустом выборе скачивание и запуск пропускаются, включая отсутствие требования к общей сети и MQTT. Повторный `apply` безопасно применяет тот же выбор. Для управления HA и дополнениями одной командой используйте `system/ha.sh start`, `stop`, `restart` или `check`; пути и примеры приведены в [основной инструкции](../readme.md#управление-всей-системой).

Сервисы, описанные в Compose, останавливаются через `docker compose --profile '*' stop` с явным списком найденных сервисов: видны штатные статусы контейнеров, как при остановке HA. Это относится и к оставшимся контейнерам отключённых профилей. Контейнеры сервисов, уже удалённых из Compose, останавливаются отдельно через `docker stop`; перед ожиданием скрипт показывает их имена. Список сервисов определяется из Compose и меток, без имён дополнений в коде.

Само редактирование `.env` не останавливает уже созданные контейнеры, в том числе после перезагрузки. Применяйте изменения скриптом до перезагрузки. Прямое указание сервиса в `docker compose up zigbee2mqtt` обходит выключенный профиль; используйте скрипт как точку запуска и обновления. File Editor дополнительно проверяет непустые учётные данные при старте самого контейнера.

При ошибке разбора Compose, чужом владельце контейнера или сбое загрузки образа скрипт завершается до удаления отключённых контейнеров. Параметры приложений проверяются при их запуске, а запуск нескольких сервисов не является транзакцией: при частичном сбое исправьте настройки и повторите `apply`. Compose ожидает запуска или Docker healthcheck до 60 секунд. Без healthcheck состояние `running` не подтверждает работу всех функций приложения.

## Zigbee2MQTT и File Editor

Mosquitto создаёт сеть `ha-backend` в основном стеке. Zigbee2MQTT подключается к ней как к внешней сети и использует `mqtt://mosquitto:1883`; `depends_on` между независимыми проектами не применяется. Основной стек запускается первым и создаёт сеть. Параметры подключения к MQTT задаются в самом приложении; подключение и повторные попытки выполняет Zigbee2MQTT. Специальной проверки MQTT в скрипте нет. HA продолжает подключаться к брокеру через `127.0.0.1:1883` в сети хоста. File Editor не требует общей MQTT-сети.

Для Zigbee2MQTT настройте `ZIGBEE_ADAPTER_PATH`, включите профиль и выполните `apply`. В контейнере координатор доступен как `/dev/ttyUSB0`. На новой установке откройте настроенный порт `8080`, пройдите [onboarding](https://www.zigbee2mqtt.io/guide/getting-started/#onboarding), задайте MQTT-адрес, учётные данные брокера и драйвер координатора, например `zstack`. Включите frontend на внутреннем порту `8080` и интеграцию Home Assistant. На действующей установке сохраните конфигурацию сети. Проброшенного устройства достаточно для доступа к координатору; полный `privileged` дополнению не выдаётся.

Каждое контейнерное дополнение имеет свой каталог: [zigbee2mqtt/](zigbee2mqtt/README.md) и [hass-configurator/](hass-configurator/README.md). Данные Zigbee хранятся в `addons/zigbee2mqtt/data/`, собственные настройки редактора — в `addons/hass-configurator/data/`. Они монтируются в `/app/data` и `/config` соответственно. File Editor дополнительно открывает существующий `${HA_DIR}/config` в `/hass-config`; Docker откажет в запуске при отсутствии этого каталога и не создаст пустую копию. Сохраняйте весь `data/` при резервном копировании и не создавайте новую Zigbee-сеть поверх существующей конфигурации.

По умолчанию веб-интерфейсы слушают loopback. Для временного доступа используйте SSH-туннель, выполнив на компьютере:

```bash
ssh -L 8080:127.0.0.1:8080 -L 3218:127.0.0.1:3218 hauser@192.0.2.10
```

После этого доступны `http://127.0.0.1:8080` и `http://127.0.0.1:3218`. Для постоянного доступа из LAN задайте `ADDONS_BIND_IP`. При изменении портов хоста измените туннель и мониторы. File Editor использует HTTP с авторизацией.

## Matter Server

[Инструкция Matter Server](matter-server/README.md) описывает включение профиля `matter-server`, подготовку сертификатов, сетевой интерфейс, Bluetooth, подключение интеграции в HA и обслуживание. Данные контроллера хранятся в `addons/matter-server/data/` и входят в отдельный архив `addon-matter-server-МЕТКА.tar.gz` при запуске общего скрипта бэкапа; `МЕТКА` — дата и время копии.

По умолчанию профиль выключен. Сервер использует сеть хоста и порт `5580`; `ADDONS_BIND_IP` и переназначение портов веб-интерфейсов на него не действуют. Параметры Matter задаются в `addons/.env`; основной Compose их не использует.

## Обновление и резервное копирование

Шаблон фиксирует Zigbee2MQTT `2.14.3` и File Editor `0.6.0`; существование тегов проверяется по [релизам Zigbee2MQTT](https://github.com/Koenkk/zigbee2mqtt/releases) и [Docker Hub File Editor](https://hub.docker.com/r/causticlab/hass-configurator-docker/tags). Для Matter сохранён прежний образ с тегом `stable`, переопределяемый через `MATTER_SERVER_IMAGE`; этот тег меняется со временем. Версии и digest выбираются в локальном `.env` после проверки совместимости, примечаний к релизу и резервного копирования. `addons.sh apply` скачивает только выбранные дополнения; не используйте `--profile '*' pull` в обслуживании. Ротация Docker-логов настроена на три файла по 10 МБ для каждого дополнения.

Для согласованного бэкапа используйте [system/backup.sh](../system/backup.sh). Он требует явного ввода `yes` перед остановкой сервисов, вызывает `ha.sh stop`, создаёт отдельный архив каждого каталога дополнения, общий `addons-config-МЕТКА.tar.gz` с Compose и `.env`, а также отдельный архив Home Assistant. Одинаковая метка даты и времени добавляется в имя каждого архива и папки копии, например `addon-matter-server-20261109-184400-123456+0300.tar.gz`. После копирования он вызывает `ha.sh start`, затем проверяет архивы и считает SHA-256. Отключённые дополнения тоже сохраняются. Запускать можно из любого каталога:

```bash
sudo bash /home/hauser/home_assistant_config/system/backup.sh
```

Скрипт требует root и до остановки проверяет чтение рабочих файлов, доступность Docker, запись и свободное место. `sudo bash /home/hauser/home_assistant_config/system/backup.sh --check` выполняет только предварительные проверки без остановки, архивов и постоянных файлов отчёта. `--verbose` показывает полный вывод команд, `--plain` отключает оформление и анимацию.

Архивы, `backup.log` и `result.json` находятся в `backups/ДАТА-ВРЕМЯ…/` в корне проекта. Консоль и JSON отдельно показывают результат бэкапа и запуска сервисов, длительность и простой; при остановке и запуске виден собственный вывод Docker. После завершения каталог и файлы копии передаются пользователю, вызвавшему `sudo`, с правами `700` для каталогов и `600` для файлов. При ошибке или прерывании после начала остановки скрипт пытается вернуть систему в работу, сохраняет `FAILED` и завершается с ненулевым кодом. `SUCCESS` появляется только после успешного копирования, запуска и проверки. Подробности, доступ к прежним копиям, нестандартные пути и восстановление описаны в [основной инструкции](../readme.md#резервное-копирование). Сохраняйте копию на другом устройстве.

Конфигурация HA, которую редактирует File Editor, и компоненты HACS, установленные непосредственно в `homeassistant/config/`, входят в `homeassistant-МЕТКА.tar.gz`. Для ручных интеграций архив HA сохраняет настройки, симлинки и записи версий из `config/integration-versions/`; клоны скачиваются заново по [инструкции интеграций](../integrations/readme.md#восстановление). Настройки редактора в `addon-hass-configurator-МЕТКА.tar.gz` не включают общую конфигурацию HA. Образы не удаляются при отключении; очистку выполняйте отдельно после проверки обновления. Рабочее содержимое `addons/*/data/`, файлы `.env` и бэкапы исключены из Git; в каталогах данных отслеживаются только пустые `.stub`.

## Как добавить новое контейнерное дополнение

Новое дополнение добавляется через Compose, `.env` и собственную папку. **Менять `system/addons.py` не требуется:** скрипт получает все сервисы и профили из Compose и управляет их контейнерами по меткам проекта. Он не содержит списка дополнений и не проверяет настройки приложений.

Контейнер автоматически не появляется в списке интеграций или боковой панели HA. Подключение к Home Assistant настройте по документации приложения: в Home Assistant Container нет Supervisor и магазина его дополнений.

1. Найдите официальный образ с поддержкой архитектуры сервера, выберите конкретный тег или digest. Уточните внутренние порты, каталоги данных, авторизацию и протокол подключения к HA.

2. Создайте `addons/my-addon/README.md` и заранее подготовьте `addons/my-addon/data/` с пустым файлом `.stub`, чтобы каталог появлялся при клонировании. Все рабочие файлы приложения храните в `addons/my-addon/data/`; в Git разрешён только его пустой `.stub`. Если нужны несколько монтирований, используйте подкаталоги `data/config`, `data/database` и т. п.

3. Добавьте сервис в `addons/docker-compose.yml`. Ниже условный шаблон: замените образ, порты и `/data` параметрами своего приложения. Якорь логирования уже есть в общем файле.

   ```yaml
   my-addon:
     profiles: [my-addon]
     image: ${MY_ADDON_IMAGE:-registry.example.org/vendor/my-addon:1.2.3}
     restart: unless-stopped
     ports:
       - "${ADDONS_BIND_IP:-127.0.0.1}:${MY_ADDON_PORT:-8090}:8080"
     volumes:
       - ./my-addon/data:/data
     logging: *addon-logging
   ```

   Обязательно задайте `profiles`, иначе сервис станет включённым по умолчанию. `container_name` необязателен: Compose может сформировать имя. Для нескольких контейнеров одного дополнения назначьте им один профиль и настройте `depends_on`; скрипт автоматически обработает все выбранные сервисы. Без необходимости не выдавайте полный доступ к хосту или Docker-сокету.

4. Добавьте в `.env.example` переменные `MY_ADDON_IMAGE`, `MY_ADDON_PORT` и пустые секреты, **сохранив `COMPOSE_PROFILES=`**. Пользователь сам заполняет параметры приложения в своём `.env` или `my-addon/data/`. Для необязательного сервиса не используйте `${PASSWORD:?...}` в общем Compose: интерполяция обрабатывает и отключённые сервисы. Если приложение допускает запуск без нужного секрета, используйте его штатный способ запрета такого запуска либо проверку в команде контейнера, как у File Editor; проверка не должна зависеть от Python-скрипта.

5. Если нужен MQTT, добавьте сервису `networks: [ha-backend]` и настройте в приложении `mqtt://mosquitto:1883` с учётными данными брокера. Сначала запускайте основной стек. `depends_on` не связывает независимые проекты; поведение при недоступном брокере и повторные подключения задаются самим приложением. Для остальных дополнений обычно достаточно сети проекта по умолчанию. HA с `network_mode: host` обращается к опубликованным портам на `127.0.0.1`, а не к DNS-именам сервисов Docker.

6. Опишите в `my-addon/README.md` нужные настройки, подключение к HA, содержимое `data/`, порядок обновления и бэкапа. При необходимости задайте Docker `healthcheck` прямо в сервисе: `apply` ожидает его, а `check` проверяет состояние.

7. Получите изменения в серверном клоне через `git pull --ff-only` по [основной инструкции](../readme.md#обновление-существующей-установки). Дополните существующий `addons/.env` новыми параметрами, добавьте `my-addon` в `COMPOSE_PROFILES`, выполните `addons.sh validate`, `apply`, `check`. `validate` проверяет только Compose и профили; работу приложения и связь с HA проверьте отдельно.

8. Удалите профиль из `.env`, снова выполните `apply` и убедитесь, что контейнеры удалены, а `my-addon/data/` сохранён. Повторное включение должно восстановить настройки. Проверяйте только изменённый сервис и затронутые команды; перебор сочетаний профилей не требуется. Общие локальные проверки: `python3 -m unittest discover -s tests -v`; они используют настоящий Compose и имитацию Docker daemon без скачивания образов. Тест с произвольным новым дополнением подтверждает, что правки Python не нужны.
