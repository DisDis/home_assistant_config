# Гирлянда Liana через MQTT

Пример добавляет ESP с прошивкой [Liana](https://github.com/Vasil-Pahomov/Liana) в Home Assistant штатной интеграцией MQTT. Управление собрано в одном [YAML-пакете `garland1.yaml`](garland1.yaml): питание, яркость, выбор анимации и длительность текущего эффекта. [Карточка `dashboard.yaml`](dashboard.yaml) добавляет управление на панель.

| Параметр | Значение в примере |
| --- | --- |
| Топик команд | `homeassistant/garland_control` |
| MQTT Client ID самой ESP | `garland1` |
| Веб-интерфейс ESP | <http://192.168.50.225/> |

Команды отправляются брокеру MQTT. IP ESP нужен только для её веб-интерфейса. Client ID `garland1` задаётся **на ESP**; у HA должен быть другой Client ID, иначе брокер будет разрывать одно из соединений. Поле `unique_id` в YAML — идентификатор сущности HA, а не Client ID MQTT. Само имя топика с префиксом `homeassistant/` не включает автоматическое обнаружение: в [MQTT-коде Liana](https://github.com/Vasil-Pahomov/Liana/blob/master/src/mqtt.cpp) нет отправки discovery-конфигурации.

## Подключение

1. Убедитесь, что в **Настройки → Устройства и службы** добавлена интеграция MQTT, подключённая к тому же брокеру, что и ESP. Для основного стека этого репозитория HA использует `127.0.0.1:1883`. На ESP указывается LAN-адрес **сервера MQTT**, её собственный Client ID и топик из таблицы. Учётные данные брокера задаются в интеграции HA и веб-интерфейсе ESP; в пакет их добавлять не нужно.

2. На сервере скопируйте пакет в рабочую конфигурацию. Команды выполняются из корня существующего клона репозитория; `cp -i` запросит подтверждение, если файл с таким именем уже есть:

   ```bash
   cd /home/hauser/home_assistant_config
   mkdir -p homeassistant/config/packages
   cp -i examples/liana/garland1.yaml homeassistant/config/packages/garland1.yaml
   ```

   Файл окажется в `/config/packages/garland1.yaml` внутри контейнера HA. `examples/` хранит образцы; HA не читает эту папку автоматически.

3. В `homeassistant/config/configuration.yaml` подключите [пакеты HA](https://www.home-assistant.io/docs/configuration/packages/):

   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```

   Если `homeassistant:` уже есть, добавьте `packages:` внутрь существующей секции. Если уже используется `!include_dir_named packages`, достаточно скопировать файл. Если пакеты перечислены явно, добавьте в существующий словарь `packages:` строку `garland1: !include packages/garland1.yaml`. Не создавайте второй ключ `homeassistant:` или `packages:`. Файл примера предназначен для `!include_dir_named`, а не `!include_dir_merge_named`.

   Если в основной конфигурации уже есть ручные MQTT-сущности, используйте одинаковый словарный формат `mqtt:` → `light:`, `number:` со списками сущностей: пакеты объединяют такие списки. Не смешивайте его с форматом `mqtt:` → `- light:`. Пример такого словаря:

   ```yaml
   mqtt:
     light:
       - name: "Другой светильник"
         command_topic: other_light/set
   ```

   Это пояснение формата, добавлять другого светильника не требуется. Существующую интеграцию MQTT и её подключение к брокеру сохраните.

4. Проверьте конфигурацию запущенного HA и только при успешной проверке перезапустите сервис:

   ```bash
   cd /home/hauser/home_assistant_config/homeassistant
   docker compose exec homeassistant python -m homeassistant --script check_config --config /config
   ```

   После завершения с кодом `0`:

   ```bash
   docker compose restart homeassistant
   ```

5. В интеграции MQTT появится устройство **Гирлянда Liana** и две сущности: `light.garland1`, `number.garland1_duration`. Откройте редактирование панели, добавьте ручную карточку и вставьте содержимое [`dashboard.yaml`](dashboard.yaml). Яркость и выбор анимации доступны в подробном окне сущности света. Если HA уже присвоил сущностям другие ID, замените их в карточке: `default_entity_id` задаёт ID только при первом добавлении, а при совпадении HA добавляет суффикс.

Если ранее был установлен пример с выбором палитры, обновите рабочий `homeassistant/config/packages/garland1.yaml`, выполните проверку и перезапуск из шага 4, затем замените YAML карточки содержимым нового `dashboard.yaml`.

## Поведение устройства

- **Обратной связи по MQTT нет.** В [исходнике](https://github.com/Vasil-Pahomov/Liana/blob/master/src/mqtt.cpp) ESP только подписывается на команды; состояние и MQTT Last Will не публикуются. Поэтому включён `optimistic: true`, без вымышленных `state_topic` и `availability_topic`. HA показывает последнее отправленное значение, а не подтверждение от устройства. Изменения через веб-интерфейс, случайный перебор, ночной режим и перезагрузка ESP могут расходиться с показаниями HA. Доступность ESP так не определяется; начальное значение длительности может быть неизвестно до первой команды.
- **Команда `on` запускает начальную анимацию.** В пакете стоит `on_command_type: first`: при включении с выбранным эффектом сначала отправляется `on`, затем настройки, чтобы `on` не сбросила выбор. Обычное включение или изменение яркости через сущность света также может запустить начальную анимацию.
- **Длительность относится к текущему эффекту.** Сначала выберите анимацию, затем задайте время в секундах. Выбор анимации или смена палитры через веб-интерфейс ESP сбрасывает таймер прошивки. `duration=0` разрешает немедленно продолжить случайный перебор у включённой гирлянды; выключенную гирлянду эта команда не включает. Значение в HA не является обратным отсчётом или постоянной настройкой интервала. Верхняя граница поля в примере — `86400` секунд (сутки).
- **Список эффектов зависит от прошивки.** Индексы и подписи взяты из [`effects.cpp`](https://github.com/Vasil-Pahomov/Liana/blob/master/src/effects.cpp) и [`config.h`](https://github.com/Vasil-Pahomov/Liana/blob/master/src/config.h) ветки `master`. Сверьте их со своей установленной версией. Число перед двоеточием отправляется в команду, поэтому его нельзя менять при переименовании пункта. Для эффекта `100: Магия` нужен веб-интерфейс с доступом к датчикам ориентации телефона; HA только выбирает анимацию.
- **Команды передаются без retain.** Все параметры отправляются обычным текстом с завершающим пробелом, как рекомендует [описание MQTT-команд Liana](https://github.com/Vasil-Pahomov/Liana#mqtt-operation). В этом едином топике идут разные команды, поэтому сохранение только последней retained-команды не восстановит все настройки после подключения.

## Ручная проверка команды

В **Инструменты разработчика → Действия** можно выполнить:

```yaml
action: mqtt.publish
data:
  topic: homeassistant/garland_control
  payload: "brightness=128 "
  qos: 0
  retain: false
```

Другие сообщения в тот же топик: `on`, `off`, `animation=5 `, `duration=300 `, `brightness up`, `brightness down`. В числовых командах сохраняйте завершающий пробел. Ручная отправка и относительные команды яркости не обновляют оптимистичные сущности HA. Для проверки доставки можно подписаться на `homeassistant/garland_control` через интеграцию MQTT; получение команды брокером не подтверждает её выполнение ESP.

Справочники Home Assistant: [MQTT Light](https://www.home-assistant.io/integrations/light.mqtt/), [MQTT Number](https://www.home-assistant.io/integrations/number.mqtt/).
